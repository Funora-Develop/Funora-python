# Ключ

Доступ к аккаунту FunPay - это одна cookie, `golden_key`. Она не ограничена по
правам: у того, кто её знает, есть аккаунт целиком - переписка, лоты, деньги.

Отсюда всё устройство этой главы.

## Как передать ключ

=== "Из переменной окружения"

    ```python
    from funora import Client, EnvSecretProvider

    with Client(EnvSecretProvider()) as client:
        ...
    ```

    Читается `FUNORA_GOLDEN_KEY`. Префикс меняется:
    `EnvSecretProvider(prefix="MYBOT_")`.

=== "Из файла"

    ```python
    from pathlib import Path

    from funora import Client, FileSecretProvider

    provider = FileSecretProvider(Path("~/.config/funora").expanduser())

    with Client(provider) as client:
        ...
    ```

    Ключ лежит в файле `golden_key` в этом каталоге. Можно указать и сам файл -
    провайдер принимает оба варианта.

    На POSIX права файла проверяются: доступный на чтение кому попало
    отвергается с `SecretNotFoundError`. На Windows прав в этом смысле нет, и
    проверка не делается - молча, потому что проверять нечего. Отключается она
    `check_permissions=False`.

=== "Своим способом"

    ```python
    from funora import CallableSecretProvider, Client


    def from_my_vault(name: str) -> str:
        """Достаёт секрет из хранилища.

        Аргументы:
            name (str): Имя секрета, например golden_key.

        Возвращает:
            str: Значение секрета.
        """
        return my_vault.read(name)  # (1)!


    with Client(CallableSecretProvider(from_my_vault)) as client:
        ...
    ```

    1. Ваше хранилище: Vault, KMS, менеджер паролей - что угодно, что отдаёт
       строку.

## Чего делать нельзя

!!! danger "Ключ в аргументе командной строки"

    ```bash
    python mybot.py --golden-key 0123456789abcdef  # так - нет
    ```

    Аргументы видны в списке процессов **любому** пользователю машины и
    остаются в истории оболочки. Это не теоретическое возражение: именно так
    ключи и утекают.

!!! danger "Ключ в коде и в репозитории"

    Строка в исходнике попадает в git, а из git - навсегда. Даже если её оттуда
    убрать, она останется в истории у всех, кто уже склонировал.

!!! danger "Ключ в issue, логе или скриншоте"

    Сюда же - сырой HTML страницы под авторизацией: в нём ключ не лежит, но
    лежит достаточно, чтобы вас опознать, и вся ваша переписка. Если нужно
    показать разметку - снимайте [структурный
    скелет](../observing.md), он для этого и сделан.

## Что SDK делает, чтобы ключ не вытек случайно

Ключ внутри обёрнут в тип `Secret`. У обёртки переопределены `__repr__` и
`__str__`: в трассировке, в логе и в отладчике вместо значения выводится
заглушка.

```python
from funora import Secret

value = Secret("0123456789abcdef")
print(value)          # Secret(<redacted>)
print(f"{value!r}")   # Secret(secret=<redacted>)
```

Достать значение можно только явно - методом, который так и называется. Это не
защита от злого умысла, а защита от `print` в отладке, попавшего в общий лог.

!!! note "Обёртка не спасает от того, что вы напечатаете сами"

    `print(value.reveal())` напечатает ключ. Обёртка делает утечку **заметной**
    в коде, а не невозможной.

## Если ключ протух

Площадка выдаёт новый `golden_key` при входе с нового устройства, и старый
перестаёт работать. SDK узнаёт это не по коду ответа - страница отдаётся с
обычным `200`, - а по разметке: у гостя другое меню.

Отказ приходит как `AuthenticationError`. Подробнее - в главе про
[ошибки](errors.md).
