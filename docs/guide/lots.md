# Лоты и витрина

Три страницы площадки показывают лоты, и это три разные страницы с разными
данными. Путать их дорого.

| Что | Метод | Чьи лоты | Зачем |
|---|---|---|---|
| Свои лоты в разделе | `client.lots.list_own(node_id)` | ваши | **идентификатор предложения** |
| Витрина продавца | `client.lots.showcase(user_id)` | чьи угодно | больше полей, но без идентификатора |
| Публичный список раздела | разбор есть, операции нет | всех продавцов | цены конкурентов |

## Свои лоты

```python
from funora import Client, EnvSecretProvider

with Client(EnvSecretProvider()) as client:
    page = client.lots.list_own("1234")

    for lot in page.lots():
        print(lot.offer_id.value, lot.price_text.or_none(), lot.description_text.or_none())
```

Записи достаются методом `lots()`.

### Зачем она, когда есть витрина

Витрина показывает те же лоты и даже **больше** полей - количество и признак
автовыдачи. Не даёт она одного: **идентификатора предложения**. Там он спрятан
в строке запроса ссылки.

Здесь он лежит атрибутом строки. Идентификатор нужен всем операциям записи над
лотами - а значит, эта страница нужна раньше, чем они будут написаны.

### Чего в записи нет

**Признака «лот показывается в выдаче».** Его на странице нет ни одного: все
строки структурно одинаковы, различающего класса нет, переключателя у строки нет.

Поле не выдумано нарочно. Выдумать его значило бы сказать продавцу «лот скрыт»
о показанном либо наоборот.

!!! note "Узел с говорящим именем им не является"

    В разметке есть `.tc-visible-inside`, и по имени это похоже на признак
    видимости. Это не он: тот же класс есть на **публичной** витрине профиля,
    которую видит любой посетитель. Наличие определяется набором колонок, а не
    состоянием лота.

### Кнопка поднятия

```python
page = client.lots.list_own("1234")
print(page.raise_game_id.or_none(), page.raise_node_id.or_none())
```

Это данные кнопки «поднять лоты», лежащие на странице. Самой операции поднятия
нет: запроса, которым она делается, никто не наблюдал. Данные объявлены затем,
чтобы наблюдение поднятия не пришлось делать вслепую.

## Витрина продавца

```python
from funora import Client, EnvSecretProvider

with Client(EnvSecretProvider()) as client:
    page = client.lots.showcase("987654")

    print(page.sections_total, page.offers_total)
    for section in page.sections():
        ...
```

Витрина устроена разделами, а не плоским списком, и у неё своя мера полноты:
`capped_sections` - разделы, показанные не целиком.

## Публичный список раздела

Разбор написан и проверен, **операции нет**. Причина не в лени.

`market.offers` объявлена контрактом возвращающей `Offer[]`, а `Offer` требует
обязательными идентификатор, цену и раздел. Ни одного из трёх со страницы не
собрать: идентификатор чужого предложения лежит в строке запроса ссылки, цена
наблюдается текстом, а валюта не наблюдается вовсе.

Собрать `Offer` из того, что есть, значило бы выдумать три обязательных поля из
пяти.

!!! warning "Ловушка, ради которой эта страница вообще разбиралась"

    У строки списка есть атрибут `data-user`. По имени - продавец. На деле он
    есть у строки **тогда и только тогда, когда предложение поднято**.

    Разбор по нему отдал бы продавца у поднятых предложений и промолчал бы про
    все остальные - и выглядел бы работающим: поля заполняются, ошибок нет, а
    поднятые предложения показываются первыми и попадают в глаза первыми.

    Настоящий продавец лежит в другом атрибуте, у аватара внутри строки.

Разбором можно пользоваться напрямую, если вы понимаете, что делаете:

```python
from funora._market import parse_market  # (1)!
```

1. Модуль приватный, и имя начинается с подчёркивания не случайно: это не часть
   публичного API, и меняться он может без предупреждения.
