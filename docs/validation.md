## Что сверено

Сопоставлены `Funora.zip`, рабочие копии Python SDK и спецификации, их история

[FunPayCardinal](https://github.com/sidor0912/FunPayCardinal/tree/65f5f431e3a1d9843a40414ec81e55b44cb08736).

уже была новее архива. Окружения Windows из архива не переносились в пакет.

статус `draft`; версия собираемого пакета - `0.0.1.dev0`.
Реализованы все 35 сервисных операций текущего контракта: 24 чтения и 11 записей.
Это не означает завершения всех запланированных механизмов общего контракта.

## Исправленные нарушения

- Текст и изображения используют общий ограничитель исходящих и долговечный
  журнал попыток. Загрузка изображения и его отправка расходуют бюджет отдельно.
- Потеря ответа отправки и неожиданный HTTP-статус дают неопределённый исход;
  транспорт не повторяет сообщение. Для текста сохраняется сверка с перепиской.
- Сбой канала переводит наблюдение на чтение страниц; ответ 429 включает общую паузу.
- Файловые журналы и очередь записываются атомарно под блокировкой процессов.
  Повреждённое состояние не подменяется пустым журналом. Конкурирующие постановки
  одинакового задания принимаются ровно один раз.
- Зафиксированный результат очереди сохраняется после сбоя удаления файла.
  Задание с неизвестной судьбой не отправляется повторно автоматически.
- Ошибка обработчика одного задания сохраняет остальные задания в очереди.
  Повторный запуск бота не перехватывает владельца работающего цикла.
- Отказ постановки автовыдачи отражается состоянием `queue_failed` и уведомлением
  обработчика удержания, а не остаётся ложным `queued`.
- Правка цены сохраняет выбранные значения, radio и значения checkbox; повторные
  многозначные поля отклоняются, если их нельзя сохранить без потери.
- Резервирование общего бюджета атомарно между потоками. Запоздавшая временная
  метка не пополняет один и тот же интервал второй раз.
- README и руководство исправлены там, где уже существовавшие операции были
  объявлены отсутствующими. Ссылки на исходники работают и в собранном сайте.

## Продолжение доработки

- Каталог кэшируется по TTL контракта, сбрасывается при смене сессии и ошибке
  протокола. Есть принудительное обновление; восемь параллельных async-вызовов
  одного клиента выполняют один запрос. Неполные данные не попадают в кэш.
- Отзывы доступны по страницам через `ReviewsCursor` в обоих клиентах. Курсор
  берётся из формы, принадлежит конкретному продавцу; чужое значение отклоняется
  до сети, повторённое сервером - типизированной ошибкой.
- Исправлен LRU гашения событий и его восстановление после сортировки JSON.
  Старый формат принимается, но точный прежний порядок обращений восстановить
  невозможно. Повреждённое состояние отклоняется.
- Исправлены двойной счёт попыток после 429, обход предела `Retry-After` через
  общую паузу и учёт окна ограничений при начале виртуального времени с нуля.
- Публичный ответ не подтверждает авторизацию. Пользовательский текст внутри
  виджета отзывов не принимается за страницу captcha или блокировки.
- Набор `retries` ведёт настоящий цикл чтения с виртуальными часами. Проверены
  успешный ответ, ошибки транспорта, неповторяемый и предварительный отказ,
  исчерпание попыток, `Retry-After` и его предел. Раннер отклоняет поддельную
  паузу и невыполненное ожидание; ожидаемые ответы не влияют на адаптер.

## Публичный транспорт и квоты аккаунтов

- `market.offers`, `market.snapshot` и `market.chips` используют отдельные
  HTTP-клиент, пул соединений, cookie jar и ядро разбора. `golden_key` туда
  не передаётся. `Client(public_only=True)` и `AsyncClient(public_only=True)`
  позволяют читать эти три операции без секрета.
- Блокировка публичной страницы не останавливает личные операции. При этом
  общий предел сетевой идентичности и пауза после HTTP 429 остаются общими:
  отдельная полоса не увеличивает допустимую нагрузку.
- Готовые транспорты обеих полос должны быть разными; публичный не принимает
  секрет. При подмене личного транспорта публичный задаётся явно, чтобы тест
  не мог неожиданно обратиться к реальной сети. Публичный драйвер отклоняет
  запрос записи до транспорта.
- `account_id` выбирает собственную квоту аккаунта под общим сетевым пределом.
  Один ключ делит одно ведро между клиентами; значение `self` объединяет
  клиентов без явно заданного ключа. Ключ не подтверждает авторизацию.
- Выбранный прокси теперь передаётся HTTP-клиенту до создания подключения.
  Раньше пул выбирался после создания транспорта и выбор не влиял на запрос.
- Восемь одновременных синхронных чтений создают один публичный пул.
  Закрытие клиента закрывает обе полосы; повторное чтение не создаёт новый пул.
- Генератор отклоняет снятие публичной полосы, замену ограничителя сообщений
  и отключение обязательной полноты снимка. Проверены повреждения каждого
  из этих объявлений, включая отдельный маршрут чипов.
- Из реестра сняты шесть подтверждённых пунктов: публичная полоса, квоты
  аккаунтов, подключение ограничителя и его привязка в контракте, `SendResult`
  и полнота снимка. Квота действий записи закрыта следующим изменением ниже;
  после доработок ниже в реестре осталось 24 записи.

## Квота действий записи

- По умолчанию `Budget()` включает `host`, `account` и `write`. Единица
  `actions_per_hour` порождается из контракта; её удаление или подмена
  отклоняется генератором.
- Все 11 операций записи резервируют одну единицу `write` перед первым
  изменением, атомарно с сетевыми квотами. Ведро общее для сетевой идентичности,
  включая разные аккаунты. При отказе любого ведра остальные не списываются.
- Загрузка изображения и отправка сообщения тратят одно действие и два
  HTTP-запроса. Неопределённый исход не возвращает действие в квоту.
  Безопасные POST-запросы чтения не расходуют действия и проходят при пустом write.
- Исправлен пропущенный сетевой расход сохранения цены и видимости лота.
  Форма проверяется до резервирования; прежняя цена сохраняется в аудит до
  отправки. Неизменная строка цены и уже установленная видимость не вызывают
  повторного сохранения и не расходуют действие.
- Conformance учитывает отдельные аккаунты и признак начала действия. Новые
  сценарии проверяют общий сетевой предел, залп записи, несколько запросов
  одного действия и исчерпание запаса отдельно от сетевого бюджета.
- Квота остаётся ведром токенов с предварительными числами, а не жёстким
  скользящим окном «60 за любой час». Состояние общее в процессе и сбрасывается
  при перезапуске. Долговечный ограничитель сообщений действует дополнительно.

## Профиль возможностей

- Каждая `CapabilityEvaluation` содержит `state`, `evaluated_at` и `source`.
  Начальная таблица, результат операции и сброс после отказа различаются.
  Состояние и основание хранятся одной записью, снимки не меняются задним числом.
- `capabilities()` не обращается к сети. Параллельное получение снимков не
  запускает пробы; сброс и снимок одной полосы защищены общей блокировкой.
- Ошибка авторизации или протокола инвалидирует наблюдения своей полосы.
  Начальные запреты сохраняются; сетевой сбой не освежает прежнее наблюдение.
  `resume()` сбрасывает обе полосы и устаревший кэш проверки сессии.
- Публичные оценки соединяются с личными без потери времени и основания.
  Дата общего снимка не предшествует включённой в него публичной оценке.
- Модель, поля и состояния сверяются со схемами; подмена каждого правила
  профиля отклоняется генератором. Три устаревшие записи реестра закрыты.

## Переносимые курсоры пагинации

- `chats.history_before` принимает прежний `before_message_id` либо сохранённый
  `cursor`. `ChatHistory.next_cursor` берётся от наименьшего идентификатора
  полного ответа, а при подтверждённом конце равен `None`. Неполная страница
  отказывает в получении следующего курсора, чтобы не пропустить повреждённые строки.
- `ReviewsCursor.to_token()` и `from_token()` сохраняют позицию отзывов;
  `reviews.get` принимает и прежний объект, и строку. Проверены sync/async
  и продолжение в другом экземпляре клиента.
- Общий формат проверяет версию, каноническую форму, семейство адаптера,
  операцию и владельца до сети. Отвергаются чужие и неканонические токены,
  повторённые ключи JSON, неверные типы, глубокая вложенность и размер свыше
  16 KiB. Сырой указатель сервера сохраняется без нормализации Unicode.
- Единая проверка позиции применяется к аргументам и идентификаторам ответа.
  Unicode-цифры, неподдерживаемая длина и огромные целые не приводят к
  нетипизированному исключению. Повреждённый ответ сохраняет годные строки
  и сообщает неполноту.
- Генератор отклоняет неподдерживаемый формат и ложные целочисленные параметры
  (`true` или `1.0` вместо `1`). Схема `ChatHistory` сверяется с полями модели.
  Обновлены прежние утверждения руководства об отсутствии догрузки.

## Точная арифметика бюджета

- Исправлен повторный отказ после рассчитанной паузы: запас, право на залп,
  доли и восстановление ёмкости больше не накапливают двоичную погрешность.
  Монотонные секунды принимаются прежним API; внутри используются точные дроби.
- Ожидание запаса, снятого класса и остывания округляется только на выходе.
  Векторы требуют точные метки, включая сдвиг начала часов и дробную стоимость.
- Отрицательная и неконечная стоимость, неконечное время отклоняются до
  изменения состояния. Атомарность вложенных вёдер и общий lock сохранены.
- Математическая точность закрывается тестами без наблюдения HTTP 429.
  Настоящие пределы площадки остаются предварительными; получение 429
  намеренно не провоцируется.
- Обновлены устаревшие утверждения документации о числе операций и статусе
  канала обновлений.

## Поиск каталога

- `catalog.search(query)` добавлен в sync/async клиент и публичную полосу.
  Наблюдённый POST `/games/promoFilter` передаёт только `query`, JSON-ответ
  содержит `html`. Запрос не использует cookie аккаунта.
- Переиспользуются `CatalogPage`, варианты и разбор разделов. Сохраняются все
  серверные совпадения и буквенные группы, включая скрытые варианты.
  `query` указывает нормализованный запрос; у полного каталога это `None`.
- Непустая выдача не доказывает число всех совпадений и возвращает `unknown`.
  Повреждения дают `partial`; явный пустой `html` допускает `complete` только
  при проверенной целостности HTTP. Неизвестный JSON отклоняется.
- Валидация выполняется до сети и списания бюджета. Публичный драйвер
  разрешает только точный поисковый POST, не пропуская другие формы и Cookie
  в его заголовках. Суточный кэш `catalog.categories` не изменяется.
- Два списка разделов с одним `data-id` больше не выбираются по случайному
  порядку: сопоставление считается неоднозначным и возвращается дефект.
- Наблюдение и проверки закрывают `catalog_search_operation`; контракт
  остаётся `draft`, в реестре остаётся 24 незавершённых пункта.

## Точные цены рынка

- `MarketOffer.price` и `SnapshotEntry.price` содержат `Observed[Money]`.
  Нормализуется показанный текст, а не более точный ключ сортировки `data-s`.
  Разрядность равна 6; округление и `float` не используются.
- Неизвестный формат, знак валюты, лишняя точность и переполнение дают
  повреждение поля, сохраняя строку и исходный текст. Ненаблюдённая цена
  не заменяется нулём. Две нормализованные цены сравниваются численно вместе
  с валютой; изменение одного оформления больше не выглядит сменой цены.
- `Money` проверяет границы знакового `int64`, целую разрядность 0-6 и точный
  код валюты. Арифметическое переполнение даёт `ValidationError`. Таблица
  знаков и границы берутся из генератора; их подмена проверяется мутациями.
- Удалён пример с `float` из руководства. Формат цены подтверждён собственным
  чтением двух страниц; создание подписок и событий рынка остаётся отдельной
  незавершённой задачей. Число открытых пунктов реестра остаётся 24.

## Сохранение непринятой партии

Добавлено 63 тестовых случая.

- Воспроизведены потеря замеченного события после смены ответа площадки,
  потеря при прерывании обработчика и обход отказа следующим событием того же ключа.
- Общий sync/async цикл сохраняет партию и целевой курсор до обработчиков.
  Повтор сохраняет id, payload и observed_at и не требует HTTP; меняется attempt.
  Принятые события удаляются после раздачи; курсор и удаление последней записи
  подтверждаются атомарно. Отказ записи не подтверждает доставку.
- После отказа блокируются следующие события того же ключа. Независимые ключи
  партии проходят, новые чтения ждут её подтверждения. Пауза не позволяет
  восстановить промежуточные изменения на площадке; гарантия относится к уже
  сохранённым событиям. При прерывании до подтверждения обработчик может повториться.
- Проверены отмена async-задачи, KeyboardInterrupt, аварийный выход процесса,
  ошибка callback, отказы записи до и после обработчиков, изменение payload
  обработчиком, сохранение исходного Unicode и микросекунд, повреждение журнала
  и несовпадение владельца. Владение файлом исключительное и освобождается при выходе.
  Символическая ссылка сохраняется: запись и блокировка используют фактический файл.
- Формат состояния v5 принимает v4 без незавершённых попыток с сохранением данных.
  Для v4 с попытками дан явный отказ: исходных событий в нём нет. Без state_path
  партия сохраняется только во время вызова watch. Пустой опрос требует одну
  запись состояния; отдельного журнала намерений без событий не создаётся.
  Кодирование и восстановление партии из 1000 событий (290 666 байт) заняло
  медиану 14,152 мс на Python 3.14.6: 7 прогонов, без файлового ввода-вывода.
- Обработчики market.* пока не добавлены: обнаруженное нарушение доставки
  исправлено как необходимая основа для дальнейшего наблюдения за рынком.

## Наблюдения рынка

Добавлены `MarketWatch`, `client.monitoring.plan(...)` и
`client.monitoring.watch(...)` для обоих клиентов. Локальный runtime использует
публичную полосу и общий бюджет. Атомарный допуск набора учитывает действующие
наблюдения того же процесса, вложенные сетевые вёдра и снижение ёмкости.
Стоимость берётся из `market.snapshot.cost_hint`; каждый HTTP-запрос всё равно
проходит обычное резервирование. Выход, исключение и отмена освобождают допуск.

История хранит номер снимка, полное основание, известные цены и счётчики
отсутствий. Рынок порождает появление, исчезновение и изменение цены; теперь
порождаются 11 из 16 объявленных видов. Неполный снимок сохраняет известные
предложения и обнуляет отсутствия. Появления молчат до первого полного снимка;
положительные изменения известных цен доступны и при неполноте. Исчезновение
требует двух полных снимков подряд и означает отсутствие в выдаче.

Общий `_deliver_pending` используется личным watch и рынком. ID рыночного
события включает имя наблюдения и сохранённую последовательность снимков,
поэтому возврат цены не гасится как старый повтор. Журнал сохраняет исходные
события до обработчиков; повреждённые Money, чужой набор, владелец или номер
снимка отклоняются до раздачи. Формат v6 принимает v5 без сброса; ограничение
миграции v4 с незавершёнными попытками сохраняется.

Добавлены 83 проверки: история, неполнота, повторные появления и цены,

## Проверка повреждений канала

- Опрос и отправка используют общий JSON-декодер. Дубли ключей на любой
  глубине, неконечные числа и ошибки преобразования/глубины больше не скрывают
  отказ и не останавливают наблюдение необработанным исключением.
- Для опроса обязательны `response`, `objects` и наблюдённые поля каждого
  объекта. Повтор пары `type/id`, повреждение объекта или непригодный для UTF-8
  ключ/метка отвергают весь ответ до обновления меток. Корректные неизвестные
  виды сохраняются как сигнал изменения.
- `response.error` сохраняет сырой тип: только явный `null` означает отсутствие
  отказа. Пропущенное поле при отправке даёт новую причину
  `response_error_missing` с исходом `unconfirmed`; сообщение не отправляется
  повторно. Существующая сверка текста с историей сохраняется.
- Исправлено расхождение схемы `SendResult` с уже порождаемыми причинами
  `transport_error` и `unexpected_http_status`; новая проверка сравнивает
  закрытый перечень схемы со всем перечнем классификатора.
- Sync/async проверки подтверждают немедленное чтение страниц после повреждения,
  доставку замеченного там нового заказа и возврат к экономному опросу после
  следующего понятного ответа. Отдельно проверена единственная отправка при
  повреждённом ответе и последующая сверка истории.
- Это контролируемые повреждения ответов, а не новые живые наблюдения отказов
  FunPay. `runner_error_shape` остаётся в реестре; всего незавершённых пунктов 22.

Добавлены 130 тестовых случаев. `_updates.py` покрыт на 100% (97/97 строк).
В HTTP-тесте изображения исправлен прежний неполный ответ успеха; варианты
с пропущенным и повторённым error проверяются отдельно. Глубина фикстуры,
вызывающей ошибку JSON-декодера, сверена на Python 3.11 и 3.12.

Строгий разбор измерен на Python 3.14.6: 7 серий по 10 000 разборов ответа
из двух объектов (610 байт) дали медиану 4,839 мкс против 2,988 мкс ранее.
Для 10 объектов с 300 922 байтами разметки - 208,430 мкс против 202,744 мкс
(7 серий по 100 разборов). Сетевой и файловый IO в измерение не входят.

## Чтение живой площадки и скорость

Первоначально без авторизации прочитаны

Каталог разобран полностью: 871 запись игры/варианта. Схема раздела прочитана
полностью: два поля. Сетевые времена этих двух запросов - около 1,2 секунды.
Затем без авторизации прочитаны публичный профиль и продолжения отзывов через
POST `/users/reviews`. Первые страницы содержали по 25 отзывов, форму и видимую

того же виджета; конец нефильтрованного списка целиком не обходился. Пустой
результат фильтра оценки 2 также наблюдался, но его признак не используется для
объявления любого пустого профиля полным. В Git сохранены только обезличенные
скелеты начала, продолжения и конца с происхождением в формате v9.

## Что ещё требуется для выпуска

1. Проверить авторизацию и согласованные операции на тестовом аккаунте:
   отправку и подтверждение сообщения, изображение, правку тестового лота
   с восстановлением исходного значения. Действия с деньгами требуют
   отдельного явно разрешённого сценария.
2. Перед выпуском обязательны зелёные проверки Linux и Windows в PR.
   Windows CI проверяет блокировки, состояние и очереди; локальный macOS
   не доказывает работу ветки `msvcrt`.
3. Python CI закреплён на spec `5ea538871575b26ba9aa8e54898be504bbf141ed`.
   Изменения оформляются связанными PR спецификации и Python SDK; выпуск
   пакета в PyPI в этот этап не входит.
4. Сохранять статус `draft`, пока не закрыты необходимые вопросы протокола:
   догрузка операций аккаунта и списков заказов, успешный ответ поднятия, ошибки канала, ограничения
   частоты и другие пункты плана наблюдений. Вывод средств, восстановление
   канала по позиции и приоритетная отмена запросов остаются за пределами
   выполненной реализации.

Повторяемые команды приведены в [установке и проверках](guide/install.md).
