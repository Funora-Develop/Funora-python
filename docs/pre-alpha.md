# Тестовый pre-alpha 0.0.1.dev1

Сборка предназначена для проверки интеграций и обратной связи.
Контракт `0.59.0` сохраняет статус `draft`: публичный API и форматы могут
меняться в следующих тестовых версиях. Для зависимого проекта закрепляйте
точную версию и сохраняйте резервную копию файлов состояния перед обновлением.

## Получение и установка

[Страница выпуска на GitHub](https://github.com/Funora-Develop/Funora-python/releases/tag/v0.0.1.dev1)
содержит три файла:

- `funora-0.0.1.dev1-py3-none-any.whl` - готовый Python-пакет;
- `funora-0.0.1.dev1.tar.gz` - исходный дистрибутив;
- `SHA256SUMS` - контрольные суммы обоих файлов.

Скачайте wheel и `SHA256SUMS` в один каталог. На Linux или macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install ./funora-0.0.1.dev1-py3-none-any.whl
.venv/bin/python -m pip check
.venv/bin/python -c "import funora; print(funora.__version__)"
.venv/bin/python -m funora.observe --help
```

На Windows используйте `python -m venv .venv` и путь
`.venv\Scripts\python.exe` в следующих командах. Ожидаемая версия - `0.0.1.dev1`.
Сам пакет устанавливается из скачанного файла, его две зависимости - из
настроенного индекса pip. Версия не публикуется в PyPI.

Перед установкой сравните SHA-256 wheel со строкой в `SHA256SUMS`.
На macOS используйте `shasum -a 256 funora-0.0.1.dev1-py3-none-any.whl`,
на Linux - `sha256sum funora-0.0.1.dev1-py3-none-any.whl`,
в PowerShell - `Get-FileHash funora-0.0.1.dev1-py3-none-any.whl -Algorithm SHA256`.

Первые примеры находятся в [руководстве](guide/first-run.md),
анонимное чтение рынка - в [главе о рынке](guide/market.md).

## Состав и проверки

Реализованы 35 сервисных операций: 24 чтения и 11 записей.
Доступны синхронный и асинхронный клиенты, наблюдения рынка, общий бюджет
запросов, долговечные очереди, журналы исходящих и выдач, восстановление состояния.
SDK порождает 12 из 16 объявленных контрактом видов событий.

Перед сборкой тега workflow выполняет полный CI на Linux с Python 3.11 и 3.12,
отдельный набор блокировок, состояния и очередей на Windows, проверку типов,
генератора, документации и соответствия контракту. Порог покрытия строк SDK -
100%. После сборки проверяются метаданные и установка wheel в чистое окружение.
Покрытие ветвей этим числом не заявляется. Результаты и причины пропусков
приведены в [отчёте о проверках](validation.md).

## Известные ограничения

- Авторизованные сценарии записи проверены на сохранённых и подставных ответах.
  Полный цикл на действующем тестовом аккаунте ещё не подтверждён. Начните
  с чтения; отправки и изменения проверяйте на выделенных тестовых данных.
- Нет вывода средств и догрузки длинных списков заказов и операций счёта.
  Полнота витрины и переписки на странице заказа может быть неизвестна.
- Вид успешного ответа поднятия лота, часть запроса переключения видимости
  и формы ошибок канала ещё требуют собственных наблюдений протокола.
- Нет восстановления канала по удалённой позиции и объединения одновременных
  попыток повторной авторизации (`single_flight_reauth`).
- Выполняющийся запрос не отменяется ради более приоритетного. Обычный
  синхронный обработчик нельзя прервать по таймауту; его зависание останавливает
  цикл наблюдения. Для ограничения времени используйте обработчик-сопрограмму.
- Мониторинг не сжимает промежуточные цены. Непринятая партия приостанавливает
  новые чтения; изменения за простой могут остаться ненаблюдёнными.
  При постоянно неполных снимках история старых предложений может расти.
- Не все объявленные ошибки и виды событий порождаются реализацией.
  Возможность вызвать метод сама по себе не подтверждает полноту протокола.

Полный [реестр 22 незавершённых пунктов](https://github.com/Funora-Develop/Funora-spec/blob/a1c66789b42b8d44a94a7a8489059e708c1bd0d7/spec/conformance/not-implemented.yaml)
включает также вопросы общего межъязыкового контракта. Подробные
[границы SDK](limits.md) и [план наблюдений](observation-plan.md)
сохраняются для этой версии.

## Обратная связь

В [GitHub Issues](https://github.com/Funora-Develop/Funora-python/issues)
укажите версию Funora, Python и ОС, минимальный пример, ожидаемый результат
и фактический тип ошибки. Не прикладывайте сессионный ключ, cookies, содержимое
личных переписок и необезличенные ответы аккаунта. Изменения протокола
фиксируйте через [инструмент наблюдений](observing.md).
